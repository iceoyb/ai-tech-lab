1. DeepSeek-R1: 通过强化学习激励大语言模型推理能力

问题背景

传统大语言模型在复杂推理任务（数学证明、代码生成、逻辑推理）上表现受限，主要依赖监督微调（SFT）模仿人类推理过程。DeepSeek团队提出纯强化学习（RL）路径，无需大量人工标注推理链即可激发模型的推理能力。

核心方案

DeepSeek-R1采用两阶段训练策略：

  1. DeepSeek-R1-Zero：直接在基础模型上应用GRPO（Group Relative Policy Optimization）算法，不经过SFT冷启动。模型自发涌现出"自我验证"、"反思"等推理行为。
  2. DeepSeek-R1：引入多阶段训练——先用少量冷启动数据（数千条长CoT样本）进行SFT，再进行推理导向的RL，最后通过拒绝采样生成高质量SFT数据并混合通用能力数据二次微调。

GRPO的核心优势在于去掉了PPO中的Critic网络，通过组内相对奖励估计优势函数，大幅降低训练显存开销：


# GRPO 核心损失函数（简化实现）
def grpo_loss(log_probs, old_log_probs, advantages, clip_eps=0.2):
    ratio = torch.exp(log_probs - old_log_probs)
    surr1 = ratio * advantages
    surr2 = torch.clamp(ratio, 1 - clip_eps, 1 + clip_eps) * advantages
    # 组内相对优势：同一prompt的多个response相互比较
    loss = -torch.min(surr1, surr2).mean()
    return loss

# 奖励函数设计（规则奖励，无需训练奖励模型）
def compute_reward(response, ground_truth):
    reward = 0.0
    # 准确性奖励：答案是否正确
    if extract_answer(response) == ground_truth:
        reward += 1.0
    # 格式奖励：是否包含 <think> 标签
    if "<think>" in response and "</think>" in response:
        reward += 0.5
    return reward

工程实践要点

  • 性能数据：DeepSeek-R1在AIME 2024上达到79.8% Pass@1，MATH-500上达到97.3%，与OpenAI o1-1217相当，但训练成本大幅降低。
  • 蒸馏策略：团队将R1的推理能力蒸馏到Qwen和Llama系列小模型上，DeepSeek-R1-Distill-Qwen-7B在AIME 2024上达到55.5%，超越QwQ-32B-Preview。这为资源受限团队提供了可行路径——不必从头训练，直接蒸馏即可。
  • 踩坑提醒：R1-Zero阶段会出现语言混合、可读性差的问题，冷启动SFT不可省略。RL训练中奖励函数设计需谨慎，纯结果奖励容易导致reward hacking（模型学会"猜答案"而非真正推理）。

2. Qwen2.5-VL: 增强视觉-语言模型的文档理解与Agent能力

问题背景

多模态大模型在文档解析、GUI操作、视频理解等场景面临细粒度视觉感知不足、长视频时序建模困难、结构化输出不稳定等挑战。Qwen2.5-VL在架构和训练策略上做了系统性改进。

核心方案

Qwen2.5-VL的三大架构创新：

  • 动态分辨率ViT：引入窗口注意力机制（Window Attention），仅在窗口内计算注意力，全局使用MLP聚合，将ViT的计算复杂度从O(n²)降至O(n·w)，w为窗口大小。同时引入动态FPS采样，视频帧率自适应调整。
  • MRoPE-AL（多模态旋转位置编码-对齐版）：将位置编码分解为时间、高度、宽度三个维度，文本token共享统一位置ID，视觉token按时空维度分配独立ID，实现跨模态位置对齐。
  • 绝对时间编码：视频理解中引入绝对时间戳，模型能精确回答"第3分25秒发生了什么"。

# Qwen2.5-VL 推理示例：文档解析 + 结构化输出
from transformers import Qwen2_5_VLForConditionalGeneration, AutoProcessor
from qwen_vl_utils import process_vision_info

model = Qwen2_5_VLForConditionalGeneration.from_pretrained(
    "Qwen/Qwen2.5-VL-7B-Instruct",
    torch_dtype="bfloat16",
    device_map="auto",
    # 启用Flash Attention 2 加速
    attn_implementation="flash_attention_2"
)
processor = AutoProcessor.from_pretrained("Qwen/Qwen2.5-VL-7B-Instruct")

messages = [{
    "role": "user",
    "content": [
        {"type": "image", "url": "invoice.pdf_page1.png"},
        {"type": "text", "text": "提取发票中所有字段，输出JSON格式"}
    ]
}]

# 关键：设置 min_pixels / max_pixels 控制ViT输入token数
# 高分辨率文档建议 max_pixels=1280*28*28
text = processor.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
image_inputs, video_inputs = process_vision_info(messages)
inputs = processor(text=[text], images=image_inputs, videos=video_inputs,
                   padding=True, return_tensors="pt").to(model.device)

generated_ids = model.generate(**inputs, max_new_tokens=2048)
output = processor.batch_decode(generated_ids[:, inputs.input_ids.shape[1]:],
                                skip_special_tokens=True)[0]

工程实践要点

  • 性能数据：Qwen2.5-VL-72B在DocVQA上达到96.4%，在ScreenSpot（GUI定位）上达到87.1%，显著超越GPT-4o和Claude 3.5 Sonnet。
  • 部署建议：7B版本在单张A100（40GB）上可运行，但处理高分辨率文档时建议开启flash_attention_2并合理设置max_pixels，否则显存容易溢出。实际测试中，一张2480×3508的扫描件，默认配置下ViT产生约4000个token，加上文本部分，总序列长度容易超过8K。
  • 踩坑提醒：动态分辨率意味着同一张图在不同min_pixels/max_pixels设置下结果可能不同，生产环境需固定该参数以保证一致性。

3. Mixture of Depths: 动态分配Transformer计算深度

问题背景

标准Transformer对所有token在所有层执行相同计算，但直觉上不同token所需的"思考深度"不同——虚词可能只需浅层处理，而关键实体需要深层推理。Google DeepMind提出的Mixture of Depths（MoD）让模型学会为每个token动态选择计算深度。

核心方案

MoD的核心思想是在每一层引入一个路由器（Router），为每个token打分，只有得分最高的top-k个token参与该层的自注意力和MLP计算，其余token直接跳过（残差连接传递）。


# MoD 核心机制（简化实现）
class MoDBlock(nn.Module):
    def __init__(self, d_model, capacity_ratio=0.5):
        super().__init__()
        self.attn = MultiHeadAttention(d_model)
        self.mlp = MLP(d_model)
        self.router = nn.Linear(d_model, 1)
        self.capacity = int(capacity_ratio * seq_len)  # 每层处理的token数

    def forward(self, x):
        # x: [batch, seq_len, d_model]
        router_scores = self.router(x).squeeze(-1)  # [batch, seq_len]

        # 选择 top-k token 参与计算
        top_k_scores, top_k_indices = router_scores.topk(self.capacity, dim=-1)
        top_k_indices, _ = top_k_indices.sort(dim=-1)  # 保持顺序

        # 只对选中的token做attention + MLP
        x_selected = torch.gather(x, 1, top_k_indices.unsqueeze(-1).expand(-1, -1, x.size(-1)))
        x_selected = x_selected + self.attn(x_selected)
        x_selected = x_selected + self.mlp(x_selected)

        # 将计算结果scatter回原位置
        output = x.clone()
        output.scatter_(1, top_k_indices.unsqueeze(-1).expand(-1, -1, x.size(-1)), x_selected)
        return output

工程实践要点

  • 性能数据：在等效FLOPs预算下，MoD模型比基线Transformer训练损失降低约1.5%，推理速度提升最高达50%（当capacity_ratio=0.125时）。
  • 与MoE的关系：MoD与MoE（Mixture of Experts）正交，可以叠加使用——MoE在宽度方向稀疏激活专家，MoD在深度方向稀疏选择token。论文中MoD+MoE组合在等FLOPs下达到最优性能。
  • 踩坑提醒：MoD在推理时面临KV Cache管理难题——不同token在不同层被跳过，导致KV Cache不连续。实践中建议采用静态capacity分配（每层固定处理固定数量的token），避免动态shape导致的kernel启动开销。另外，top-k选择操作在GPU上需要高效的gather/scatter实现，建议使用torch.compile或自定义CUDA kernel优化。

4. CRAG: 纠正性检索增强生成

问题背景

传统RAG系统对检索结果"照单全收"，当检索器返回不相关或错误文档时，LLM会被误导产生幻觉。CRAG（Corrective RAG）引入轻量级检索评估器，对检索结果进行置信度评估，并触发不同的纠正策略。

核心方案

CRAG的核心流程：

  1. 检索评估：使用轻量级T5模型（或微调的分类器）对每个检索文档打分，分为Correct（正确）、Ambiguous（模糊）、Incorrect（错误）三档。
  2. 知识精炼：对Correct文档，使用分解-重组算法提取关键知识条带（knowledge strips），过滤噪声。
  3. 网络搜索兜底：当所有检索文档均被判为Incorrect时，触发网络搜索（如Google Search API）获取补充信息。

# CRAG 核心流程实现
class CorrectiveRAG:
    def __init__(self, retriever, evaluator, llm, web_search):
        self.retriever = retriever      # 向量检索器
        self.evaluator = evaluator      # 检索评估器（T5-small微调）
        self.llm = llm                  # 生成模型
        self.web_search = web_search    # 网络搜索API

    def query(self, question: str) -> str:
        # Step 1: 检索
        docs = self.retriever.search(question, top_k=5)

        # Step 2: 评估每个文档的相关性
        scores = [self.evaluator.predict(question, doc) for doc in docs]
        # scores: 1 (correct), 0 (ambiguous), -1 (incorrect)

        max_score = max(scores)

        if max_score == -1:
            # 所有文档均不相关 → 触发网络搜索
            web_results = self.web_search.search(question, num_results=3)
            context = self._refine_knowledge(web_results)
        elif max_score == 0:
            # 部分模糊 → 结合检索文档 + 网络搜索
            relevant_docs = [d for d, s in zip(docs, scores) if s >= 0]
            web_results = self.web_search.search(question, num_results=2)
            context = self._refine_knowledge(relevant_docs + web_results)
        else:
            # 存在正确文档 → 知识精炼
            relevant_docs = [d for d, s in zip(docs, scores) if s == 1]
            context = self._refine_knowledge(relevant_docs)

        # Step 3: 生成
        prompt = f"基于以下信息回答问题：\n{context}\n\n问题：{question}"
        return self.llm.generate(prompt)

    def _refine_knowledge(self, docs):
        """分解-重组：将文档切分为知识条带，过滤后重组"""
        strips = []
        for doc in docs:
            for sent in doc.split("。"):
                if self.evaluator.predict_relevance(sent) > 0.8:
                    strips.append(sent.strip())
        return "\n".join(strips[:10])  # 取top-10知识条带

工程实践要点

  • 性能数据：在PopQA（长尾知识问答）上，CRAG相比标准RAG准确率提升12.3%（从38.2%到50.5%）；在Biography生成任务上，事实性准确率提升8.7%。
  • 评估器训练：检索评估器是关键组件。论文使用T5-large在标注数据上微调，输入格式为"question: {q} document: {d}"，输出三分类标签。实际部署中可替换为更小的模型（如BERT-base）以降低延迟，准确率损失约2-3%。
  • 踩坑提醒：（1）网络搜索引入额外延迟（通常500ms-2s），高并发场景需做好超时控制和降级策略；（2）知识精炼的阈值需要根据业务数据分布调优，过高会导致信息丢失，过低则引入噪声；（3）CRAG对评估器质量高度敏感，如果评估器本身不准，纠正策略会适得其反。建议先在业务数据集上评估评估器的F1分数，确保>0.85再上线。

5. LoRA-GA: 低秩适配的梯度对齐初始化

问题背景

LoRA（Low-Rank Adaptation）已成为大模型微调的事实标准，但标准LoRA使用随机初始化（A矩阵高斯初始化，B矩阵零初始化），导致训练初期梯度方向与全量微调差异较大，收敛速度慢。LoRA-GA通过对齐LoRA梯度与全量微调梯度来加速收敛。

核心方案

LoRA-GA的核心观察：标准LoRA初始阶段，BA≈0，导致梯度≈0，模型"学不到东西"。LoRA-GA通过SVD分解全量微调的初始梯度，用其奇异向量初始化A和B矩阵，使得LoRA的第一步梯度方向与全量微调一致。


# LoRA-GA 初始化实现
import torch
import torch.nn as nn

def lora_ga_init(linear_layer: nn.Linear, rank: int = 8, scale: float = 1.0):
    """
    使用梯度对齐初始化LoRA的A、B矩阵
    原理：对全量微调的初始梯度做SVD，取top-r奇异向量
    """
    W = linear_layer.weight  # [out_features, in_features]
    out_features, in_features = W.shape

    # Step 1: 估计全量微调的初始梯度（用一个batch的数据）
    # 实际实现中，需要前向+反向传播获取 ∇W
    # 这里简化为随机梯度估计
    grad_W = estimate_full_gradient(linear_layer)  # [out_features, in_features]

    # Step 2: SVD分解
    U, S, Vh = torch.linalg.svd(grad_W, full_matrices=False)
    # U: [out, out], S: [min(out,in)], Vh: [in, in]

    # Step 3: 取top-r奇异向量初始化A和B
    # B = U[:, :r] * sqrt(S[:r])  →  [out, r]
    # A = sqrt(S[:r]).unsqueeze(1) * Vh[:r, :]  →  [r, in]
    sqrt_S = torch.sqrt(S[:rank])
    B = U[:, :rank] * sqrt_S.unsqueeze(0) * scale
    A = sqrt_S.unsqueeze(1) * Vh[:rank, :] * scale

    return nn.Parameter(B), nn.Parameter(A)

# 与标准LoRA的收敛对比（实验数据）
# 在MetaMathQA数据集上微调Llama-2-7B：
# - 标准LoRA: 达到80%准确率需要 ~1200 steps
# - LoRA-GA:  达到80%准确率仅需 ~400 steps（加速3倍）
# - 最终准确率: LoRA 82.1% vs LoRA-GA 83.4%

工程实践要点

  • 性能数据：在GSM8K数学推理任务上，LoRA-GA（rank=8）达到63.2%准确率，标准LoRA为59.8%，全量微调为64.1%。LoRA-GA将LoRA与全量微调的差距从4.3%缩小到0.9%。
  • 计算开销：LoRA-GA需要额外的一次前向+反向传播来估计梯度，加上SVD分解（对7B模型的单一层约需50ms），总初始化开销约2-5分钟，相对于节省的训练时间（数小时）完全值得。
  • 踩坑提醒：（1）梯度估计的batch需要具有代表性，建议使用与正式训练相同的数据分布采样；（2）SVD分解在大矩阵上可能数值不稳定，建议使用torch.linalg.svd而非torch.svd（后者已废弃），并确保输入为float32；（3）LoRA-GA与LoRA+（差异化学习率）可以叠加使用，在A矩阵上使用更高学习率（如1e-3），B矩阵使用较低学习率（如1e-4），进一步加速收敛。

总结与趋势判断

本周精选论文呈现出三个明确趋势：

  1. 推理能力成为核心竞争力：DeepSeek-R1证明纯RL可以激发推理能力，且蒸馏路径可行。预计未来半年，更多团队将基于R1的蒸馏数据微调自有模型，推理能力将快速"平民化"。
  2. 稀疏计算走向实用：MoD和LoRA-GA分别从"深度稀疏"和"初始化优化"角度提升计算效率。在推理成本高企的当下，这类"花更少算力做更多事"的技术具有直接的商业价值。
  3. RAG系统走向"自省"：CRAG代表了RAG系统的进化方向——从被动检索到主动评估、主动纠正。生产级RAG系统需要内置质量评估和降级机制，而非简单地"检索+拼接"。

建议工程团队优先关注DeepSeek-R1的蒸馏模型（可直接部署）和CRAG的纠正机制（可直接集成到现有RAG管线），这两项技术的落地门槛最低、收益最明确。
